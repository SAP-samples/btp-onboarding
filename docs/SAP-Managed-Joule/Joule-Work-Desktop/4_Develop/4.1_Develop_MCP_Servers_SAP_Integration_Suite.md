## Develop and Connect MCP Servers with SAP Integration Suite

> **Optional** — Complete this step if you want to extend JWD with external data sources using Model Context Protocol (MCP) servers.

**MCP (Model Context Protocol)** servers are lightweight API adapters that give Joule Work Desktop access to external systems such as SAP S/4HANA, ServiceNow, databases, or any REST API. Users can then query these systems conversationally from within JWD.

**SAP Integration Suite** is the recommended platform for building and hosting your own MCP servers on SAP BTP.

### Architecture Overview

The request flow for MCP-enabled queries goes from the JWD Desktop Client to the JWD Gateway on SAP BTP, then to the MCP Server (hosted on SAP Integration Suite or any HTTPS endpoint), and finally to the backend system (SAP S/4HANA, an external API, a database, etc.). The JWD Admin Portal manages which MCP servers are available to users and which endpoints they are allowed to access via access policies.

### Prerequisites

To complete this step you will need JWD provisioned with the admin portal accessible, access to **SAP Integration Suite** on SAP BTP, and the target backend system credentials or API details.

### Step 1 — Build an MCP Server with SAP Integration Suite

SAP Integration Suite provides a runtime environment for building and exposing MCP-compatible APIs. Your MCP server must expose endpoints that conform to the Model Context Protocol specification and be accessible over HTTPS.

For detailed guidance on building MCP servers, refer to the [SAP Help Portal: SAP Integration Suite](https://help.sap.com/docs/integration-suite) and the SAP Developer tutorials for MCP Server development.

### Step 2 — Register the MCP Server in the JWD Admin Portal

Once your MCP server is deployed and accessible, navigate to the **JWD Admin Portal**, scroll to the **MCP Servers** section, and click **Add MCP Server**. Enter the display name, the HTTPS endpoint URL, and a description of what data or capabilities the server provides. Click **Save**.

### Step 3 — Configure MCP Access Policies

Access policies restrict which MCP server endpoints users can call. In the **MCP Servers** section, click **Add MCP Access Policy**, define the allowed endpoint patterns for your MCP server, and click **Save**.

> **Tip:** Start with a permissive policy for testing, then tighten access for production use.

### Step 4 — Test in JWD Client

After saving the MCP server configuration, open the JWD desktop client and navigate to **Extensions** — your MCP server should appear as an available connector. Start a conversation and invoke a capability from your MCP server, for example:

```
What are my open purchase orders?
```

If the server is configured correctly, JWD will route the request to the MCP server and return the results.

### Troubleshooting

If the MCP server is not visible in JWD, verify that the server URL is correct and accessible from the JWD gateway. If you see an **Unauthorized** error, check that the MCP server authentication is configured correctly. If no results are returned, confirm that the MCP server is running and that the access policy allows the requested endpoint.
