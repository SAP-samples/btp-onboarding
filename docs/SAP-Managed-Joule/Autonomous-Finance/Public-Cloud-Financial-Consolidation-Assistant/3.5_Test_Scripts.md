## Prerequisites

### System Access

| Requirement | Detail |
|-------------|--------|
| System | SAP S/4HANA Cloud Public Edition |
| Scope item | **1SG** must be activated |
| Joule | Access via Joule web client or standalone Joule link |
| Invoke | Use `@Financial Consolidation Assistant` to route requests |

### Global Parameters

| Parameter | Value |
|-----------|-------|
| Version | F10 |
| Fiscal year | 2027 |
| Period | 001 to 012 |
| CoA (for error message tests) | Y1 |
| Version (for error message tests) | V10 |
| Fiscal year (for error message tests) | 2021 |
| Period (for error message tests) | 012 |

### Master Data Setup

**For Data Submission Agent tests:**
- Create consolidation group, e.g., `CCGYY_AI`
- Define consolidation units and maintain group structure
- Create Profit Centers: `PC0001` to `PC0010`
- Create Segments: `SE0001` to `SE0005`
- Ensure specific FS items, Profit Centers, and Segments are **absent** when performing negative tests
- Verify that the Data Monitor task group and tasks are configured as expected

**For error message tests:**
- Create consolidation group, e.g., `CVCG1`
- Define consolidation units `CV01` and `CV02`, maintain group structure
- Create new FS Item `Z11100` (copy of `111100 Cash on Hand`) and **block it for posting**

### Test Data File

Sample file: `CGRXX_F10_UPLOAD_2027_002_SRD2_DT_WrongPC.xlsx`
- Contains wrong Profit Centers: `PC0009_B`, `PC0003_C`, `PC0008_D`
- Other Profit Centers in the file exist in the system
- First record includes an additional error due to a customized substitution/validation rule

## 4.1 — Financial Consolidation Data Submission Agent

### 4.1.1 — Global Parameters and Context

| Testing Point | Steps | Expected Result | Pass / Fail / Comment |
|---------------|-------|----------------|-----------------------|
| Test global parameters | Open Joule. Type: `@Financial Consolidation Assistant show me my tasks` | Agent prompts for global parameters if not yet provided. Supply Version, Fiscal Year, Period. Agent lists Data Monitor tasks. | |
| Change global parameters | Ask the agent to change a parameter, e.g., change the fiscal year | Agent updates the parameter and confirms | |
| Set wrong global parameters | Ask the agent to use a version that does not exist | Agent returns an error or informs the user the version is invalid | |
| Context retention | After providing global parameters, continue with several rounds of conversation / task execution in the same session | Agent retains the context throughout the session without re-asking for parameters | |

### 4.1.2 — Data Loading

| Testing Point | Steps | Expected Result | Pass / Fail / Comment |
|---------------|-------|----------------|-----------------------|
| Load data — Test Run | Click the load data button or type a prompt to trigger data loading. When prompted, choose **Test Run**. Upload the sample data file. Confirm when agent summarizes context. | Agent submits the data file in test mode and returns log information including informational messages, warnings, and errors. | |
| Load data — Update Run | Repeat with **Update Run** selected | Agent submits the data file in update mode and returns the full task log | |
| Re-load data in same session | Load data again in the same session without starting a new conversation | Agent correctly processes the re-load without confusion about context | |
| Load without cons group | Trigger data loading without providing a cons group (cons group is not mandatory for data loading only) | Agent proceeds without requiring cons group | |
| Different file formats | Upload files in `.xlsx` and `.csv` format | Agent accepts both formats and processes them correctly | |
| Cancel file picker — continue | Open the file picker, close it, click **No — continue** when prompted | Agent continues as expected and prompts for file upload again | |
| Cancel file picker — cancel | Open the file picker, close it, click **Yes — cancel** | Agent cancels the upload as expected | |
| Cancel after confirming load | After confirming the data load, attempt to cancel the execution | Execution continues; agent informs the user that the cancellation request was rejected | |
| Cancel via back button | Click the back button during data loading | Execution is cancelled | |

### 4.1.3 — Log Information and Error Reporting

| Testing Point | Steps | Expected Result | Pass / Fail / Comment |
|---------------|-------|----------------|-----------------------|
| Full task log returned | After loading data, click **Show Errors** | Agent returns log information equivalent to what is visible in the IRD app task log, including informational messages, warning information, and error information | |
| Number of posted records | Ask the agent how many records were posted | Agent returns the correct number | |
| Error recall after time | After the first time errors are shown, wait a few minutes, then ask the agent to show the errors again without loading new data | Agent understands the context and returns the previous error list | |

### 4.1.4 — Error Handling

Upload the sample file `CGRXX_F10_UPLOAD_2027_002_SRD2_DT_WrongPC.xlsx` which contains wrong Profit Centers, Segments, and FS items.

| Testing Point | Steps | Expected Result | Pass / Fail / Comment |
|---------------|-------|----------------|-----------------------|
| Detect error types | Load the sample file and view the log | Agent detects and categorizes the error types: wrong Profit Centers, wrong Segments, wrong FS items | |
| Detect occurrences | Review the error list | Agent reports the number of occurrences for each error type | |
| Propose solutions | Click **Resolve** next to an error | Agent proposes solution options: (1) treat as typo and correct, or (2) create new master data | |
| Resolve typo — Option 1 | Click **Option 1** to correct as typo | Agent suggests the correct value. User confirms. Agent corrects the data file. | |
| Create new master data — Option 2 | Click **Option 2** to create new master data | Agent prompts for required information and creates the master data (e.g., new Profit Center). Agent re-submits the corrected data. | |
| Corrected file generated | After error resolution | Agent generates a new data file with the corrections applied and suggests it to the user for review before re-submitting | |
| Re-submit only on confirmation | Agent presents the corrected file | Agent only submits the updated file when the user confirms | |
| Switch between error types | Start resolving error type A, then switch to error type B before finishing A | Agent understands the context and user intention when switching between error handling workflows | |
| Verify master data in S/4HANA | After Option 2 — create new Profit Center | Navigate to the corresponding SAP S/4HANA Public Cloud system and confirm the new Profit Center was created | |

### 4.1.5 — Negative Cases

| Testing Point | Steps | Expected Result | Pass / Fail / Comment |

## 4.2 — Error Message Test Cases

### 4.2.1 — FINRE_UI_01-007: Validation Rule Error

**Test Case ID:** TC-FINRE_UI_01-007
**Message:** `Value for field &1 doesn't comply with validation rule XXXXX`
**Example:** `Value for field Consolidation Chart of Accounts doesn't comply with validation rule HL1002_S12`
**Scope:** Data Collection tasks / Release Universal Journals — importing/entering data / releasing journals
**Objective:** Check the validation rule and correct the entry as necessary.
**Persona:** Local/Group Accountant User

**Preconditions:**
- Configure a validation rule in the **Manage Substitution/Validation Rules** app (Group journal entries). Example rule: `DM_SUBITEM_VAL2`.
  - Rule Name: DM_SUBITEM_VAL2
  - Description: Validation for subitem to be 915
  - Business Context: GR Journal Entry Item
  - Control Level: Error
  - Message Text: Value for field [Field Name] doesn't comply with validation rule DM_SUBITEM_VAL2
- The rule is exclusively triggered on Consolidation Unit: 1010
- Test environment: CoA: Y1 / Version: Y10 / Year-Period: 2025/12 / Consolidation unit: 1010

| # | Step | Instruction | Expected Result | Pass / Fail / Comment |
|---|------|-------------|----------------|-----------------------|
| 1 | Open Data Monitor | Open the Data Monitor app | Data Monitor is displayed | |
| 2 | Run data collection | Select Data collection task 1021 – Reported Data → Update Run → Import Reported data → Select the file → Import | Import runs | |
| 3 | Open the log | Open the task log after import | The error message `FINRE_UI_01-007 - Value for field [Field Name] doesn't comply with validation rule DM_SUBITEM_VAL2` is displayed | |
| 4 | Check via Joule | Ask the agent to show the errors for this import | Agent returns the same error information as the task log | |

### 4.2.2 — Other Error Messages (FINCS_DTX-003, G00-666, G00-095)

**Setup:**
- Global Parameters: CoA: Y1 / Version: V10 / Fiscal year: 2021 / Period: 012
- Cons group: CVCG1 / Cons units: CV01 (period open), CV02 (period closed)
- FS Item Z11100 (copy of 111100) — blocked for posting
- Upload file: `Import_Reported_Data – xxx.csv`

| Error | Testing Points | Expected Result | Pass / Fail / Comment |
|-------|---------------|----------------|-----------------------|
| **FINCS_DTX-003** | Run Data Collection task (1020) → Update Run → Upload file → Check task log | Error `FINCS_DTX-003 - Error occurred during 'Add mode' run. No data were posted.` should be displayed together with `G00-095 - No processing because task Data Coll. cannot be executed for any/all CGs/CUs` | |
| **G00-666** | Ensure FS Item Z11100 is blocked for posting. Upload data that includes this FS item. Check via Joule. | Warning/error for blocked FS item is returned. Note: error is not displayed in test mode in the current version of Group Reporting. | |
| **G00-095 — Closed period** | Keep period closed for CV02. Run Data Collection task (1020) → Update Run for CV02. | Error G00-095 is returned for the closed period. Note: error is not displayed in test mode in the current version of Group Reporting. | |
| **G00-095 — Blocked task** | Block the Data Collection task (preceding tasks must be run and blocked first). Attempt to run the blocked task. | Error G00-095 is returned for the blocked task. | |
