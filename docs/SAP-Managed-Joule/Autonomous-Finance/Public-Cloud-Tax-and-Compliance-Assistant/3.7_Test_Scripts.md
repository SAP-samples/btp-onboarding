## Legal Change Agent

The Legal Change Agent enables regulatory compliance discovery, allowing SAP S/4HANA Cloud users to discover, explore, and understand regulatory changes published by SAP — eliminating manual monitoring of regulatory changes via an AI-powered agentic experience.

## Statutory Report Extension Update Agent

The Statutory Report Extension Update Agent automates the merge of customer-extended objects in statutory reports in SAP S/4HANA Cloud. When SAP delivers new report versions, the extensibility implementation team on the customer side faces hours of manual work to detect impacts, analyze conflicts, and rework their extensions. The agent eliminates this by proactively detecting impacted extensions via system events, analyzing field mappings and conflicts, and generating a merged extension as a DRAFT. The user reviews the AI-proposed merge and activates when ready or instructs the agent to activate autonomously via natural language.

---

### Test 11 — Impacted Reports: View All Impacted Report Categories [Configuration Administrator]

| | |
|---|---|
| **What to do** | **Step 1:** Open the Define Statutory Reports app (F2131). **Step 2:** Click the Joule icon to open the Joule sidebar. **Step 3:** Type one of the following prompts and press Send (you may try each phrasing in a separate conversation): `@Tax Compliance Assistant show me impacted report categories` / `@Tax Compliance Assistant which of my statutory report extensions need to be updated?` / `@Tax Compliance Assistant what's my to-do list for statutory reporting extensions?` |
| **What you should expect** | The Tax Compliance Assistant returns an Impacted Report Categories table. Each row represents one report category where your system has a customer extension and SAP has delivered a newer legal change version. Columns: Report Name, Category, Country, Ext Report Def (your current extension), New LC Report (the new SAP-delivered version), and Status (e.g., Action Needed, or Draft in Progress). Below the table, the assistant provides a summary line and proactively offers to review the impact details for the first impacted category before proceeding with the merge. |
| **Notes** | |

## Statutory Report Analysis Agent

The Statutory Report Analysis Agent automates the review of statutory reports by combining: Trend Analysis (compares key figures across up to 12 historical reporting periods), Outlier Detection (automatically flags values that deviate significantly from historical patterns), Root Cause Analysis (drills into flagged outliers across dimensions such as tax codes, document types, and business partners), and Summary Generation (produces a consolidated overview of results accessible directly in the Run Statutory Reports app).

---

### Test 21 — AI-Generated Report Summary [Finance and Tax Expert]

| | |
|---|---|
| **What to do** | **Step 1:** Open the Run Statutory Reports app (F1515). **Step 2:** Generate the report run (either via Mass Action, Advance Scheduling, or Manual generation). |
| **What you should expect** | The "Review Status" column shows status "Outlier Detected" if outliers were identified (run for a period for which there are spikes). Hover over "Outlier Detected" to see an AI-generated summary containing: Key figures of the report output, Outlier reasons and root-cause details for those outliers, Recommendation to correct/analyze the outlier data in detail. Clicking the **Review Further** button navigates the user to the run screen, where a summary and the Tax and Compliance Assistant are available for in-depth analysis. Clicking the **Approve Outlier** button confirms that the user has reviewed the detected outlier and acknowledges it as a valid reflection of actual business operations. |
| **Notes** | The "Outlier Detected" badge is displayed exclusively when an outlier is identified. Runs with no detected anomalies will not show this badge in the "Review Status" column. After report run is generated successfully (or with warnings) and outlier is detected, run status will change to "Generated successfully (Review Required)". After user reviews and clicks "Approve Outlier", run status will change to "Generated with warning (Review Required)". Run log will also show the timestamp when summary is generated as well as when user approves outliers as part of audit trail. |
